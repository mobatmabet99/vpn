### Fallback Mechanism:

Jika `/etc/os-release` tidak mengenali OS ID:
1. Cek `apt-get` → Debian family
2. Cek `dnf` → RHEL family (dnf)
3. Cek `yum` → RHEL family (yum)
4. Cek `pacman` → Arch family
5. Cek `zypper` → SUSE family
6. Cek `apk` → Alpine
7. Error jika tidak ada yang ditemukan

## 🚀 v4.2.0 — XHTTP Transport (Port 80/443, Ultimate Stealth) (14 Oktober 2026)

### XHTTP: Transport Terbaru yang Paling Mirip HTTP Real

Menambahkan **4 protokol XHTTP baru** — transport terbaru Xray yang sangat mirip HTTP asli:

**Protokol XHTTP baru (v4.2)**:
- 🏆 **VLESS + XHTTP + REALITY @ Port 443** (path `/reality-xhttp`) — **BEST: Ultimate stealth, port 443**
- **VMess + XHTTP @ Port 80** (path `/vmess-xhttp`)
- **VLESS + XHTTP @ Port 80** (path `/vless-xhttp`)
- **Trojan + XHTTP @ Port 80** (path `/trojan-xhttp`)

**Total: 13 protokol per user** (9 existing + 4 XHTTP baru)

### Keunggulan XHTTP:
- ✅ **Paling mirip HTTP real** — traffic indistinguishable dari HTTP biasa
- ✅ **Port 80/443** — port website standard, anti-blocking maksimal
- ✅ **Lebih stealth dari WebSocket & gRPC** — newest Xray transport (2026)
- ✅ **Compatible dengan CDN** — Cloudflare, Nginx, Caddy support
- ✅ **Low latency** — lebih responsif dari WS untuk browsing/gaming
- ✅ **Bypass DPI** — Deep Packet Inspection tidak detect sebagai VPN

### Perubahan Breaking:
- **SSH WebSocket pindah dari port 80 → 8080** untuk menghindari konflik dengan XHTTP
  - Existing installation: manual restart `ssh-ws` jika perlu
  - New installation: otomatis pakai port 8080

### Port Mapping v4.2:

**Port 80** (Shared XHTTP):
- VMess + XHTTP (path `/vmess-xhttp`)
- VLESS + XHTTP (path `/vless-xhttp`)
- Trojan + XHTTP (path `/trojan-xhttp`)

**Port 443** (Shared REALITY):
- VLESS + TCP + XTLS-Vision + REALITY (existing)
- VLESS + XHTTP + REALITY (path `/reality-xhttp`) 🏆 **NEW & BEST**

**Port 8080**:
- SSH WebSocket (moved from port 80)

### File yang Dimodifikasi:

1. **`lib/xray.sh`**:
   - Tambah 4 inbound XHTTP dengan path routing
   - Port variables: `XPORT_XHTTP_SHARED=80`, `XPORT_VLESS_REALITY_XHTTP=443`
   - Update `xray_print_links()` untuk 13 protokol
   - Update service description: "13 inbounds: WS + gRPC + XHTTP + XTLS + REALITY"

2. **`lib/ssh.sh`**:
   - SSH WebSocket default port: 80 → 8080
   - Update dokumentasi header

3. **`install.sh`**:
   - Update description: "13 inbounds" (dari 9)
   - SSH WebSocket call: `ssh_setup_server ... 8080` (dari 80)

4. **`menu.sh`**:
   - SSH WebSocket call: `ssh_setup_server ... 8080`

### Rekomendasi Client v4.2:

**Priority order (best to fallback)**:
1. 🏆 **VLESS + XHTTP + REALITY @ Port 443** — Ultimate stealth
2. **VLESS + TCP + XTLS-Vision + REALITY @ Port 443** — Most efficient
3. **VLESS + gRPC + REALITY** — Best for CDN & heavy censorship
4. **VLESS + TCP + XTLS-Vision** — Plain XTLS

## 🚀 Cara Update dari v3 ke v4

### Opsi 1: Fresh Install (Recommended)

```bash
cd vpn
git pull origin main
sudo ./uninstall.sh         # Backup otomatis ke /root/
sudo ./install.sh --yes     # Instal ulang dengan v4
```

### Opsi 2: Update In-Place (Preserve existing users)

```bash
cd vpn
git pull origin main

# Backup config lama
sudo cp /etc/xray/config.json /etc/xray/config.json.v3.bak
sudo cp /etc/xray/params /etc/xray/params.v3.bak

# Reinstall Xray binary v26.10.10 (tetap pakai config lama)
sudo systemctl stop xray

# Download binary baru
cd /tmp
wget https://github.com/XTLS/Xray-core/releases/download/v26.10.10/Xray-linux-64.zip
unzip Xray-linux-64.zip
sudo cp xray /usr/local/bin/xray
sudo chmod 755 /usr/local/bin/xray

# Tambah inbound gRPC manual ke config.json (atau regenerate)
# Cara termudah: hapus user lama, re-create dengan v4
cd ~/vpn
sudo ./remove-xray-user.sh <nama>
sudo ./add-xray-user.sh <nama>  # Akan dapat 9 link baru

sudo systemctl restart xray
sudo systemctl status xray
```

**Catatan**: User yang dibuat di v1-v3 hanya punya 5 inbound. Untuk dapat 9 inbound v4, hapus user lama lalu buat ulang dengan `add-xray-user.sh`.

## 🐛 Known Issues & Troubleshooting

### 1. Port 10005-10008 Tertutup di Cloud Firewall

**Gejala**: Client tidak bisa connect ke gRPC ports  
**Solusi**: Buka port 10005-10008/tcp di firewall cloud provider (AWS Security Group, GCP Firewall Rules, dll)

### 2. gRPC "connection refused" di Beberapa ISP

**Gejala**: WebSocket works, gRPC fails  
**Solusi**: Beberapa ISP memblokir HTTP/2 non-TLS. Gunakan VLESS REALITY gRPC (port 10008) yang sudah pakai REALITY TLS

### 3. "stream: grpcSettings: serviceName is empty"

**Gejala**: Xray gagal start, log error serviceName  
**Solusi**: Pastikan update ke v26.10.10, versi lama tidak support `multiMode: false` default

### 4. Client Lama Tidak Support gRPC

**Solusi**: Update aplikasi client ke versi terbaru, atau gunakan WebSocket (port 10001-10003) yang masih aktif
