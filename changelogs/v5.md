## 🎉 Fitur Baru v5

### 1. **Nginx WS Gateway Terpadu (80/8080 plain + 8443 TLS + 443 via REALITY fallback)**

Satu gateway melayani semua protokol WS/XHTTP tanpa overhead config ganda
(`lib/edge.sh` baru, menu **26**):

| Port | Sifat | Routing |
|---|---|---|
| `80/tcp` | plain non-TLS | `/vmess /vless /trojan` → 10001-10003, `/vmess-xhttp /vless-xhttp /trojan-xhttp` → 10009-10011, `/ssh-ws /ssh` → 10080, `/wg-ws /wireguard-ws` → 10081 |
| `8080/tcp` | alt plain (+ `/` lama untuk klien SSH-WS lawas) | routing sama |
| `8443/tcp` | TLS (acme.sh bila ada, kalau tidak self-signed 10 tahun) | routing sama via `wss://` |
| `443/tcp` | VLESS TCP REALITY + `fallback → 127.0.0.1:8443` | WS-TLS via 443 pakai `security=tls` + SNI gateway (BUKAN pbk/sid REALITY) |

Detail robustness:

- Variabel map unik `$vpn_ws_upgrade` (hindari tabrakan `connection_upgrade` milik conf lain → `nginx -t` lolos).
- Backend XHTTP `10009-10011` kini **localhost-only** (v4.2 tiga inbound berbagi port 80 → hanya inbound pertama yang hidup; v5 tiap inbound punya port sendiri + Nginx routing per-path).
- REALITY-XHTTP pindah ke port khusus `10012` (v4.2 duplikat 443 → bind conflict; v5 tidak ada duplikat).
- Default site distro (`sites-enabled/default`, `conf.d/default.conf`, `http.d/default.conf`) dinonaktifkan otomatis (nama `.disabled-by-vpn-gateway`, dikembalikan saat uninstall).
- Path conf Alpine (`/etc/nginx/http.d/`) dideteksi **lazy** via `edge_nginx_conf()` (tidak dibekukan saat source di dev machine).
- `edge_refresh_tls()` aman di bawah `set -e` (tidak pernah `die`; skip bila nginx/conf belum ada).
- Urutan install: **wstunnel dulu (15a) → Nginx gateway (15a2)** agar gateway tidak pernah proxy ke backend yang belum ada.

### 2. **WireGuard over WebSocket via wstunnel (menu 27)**

Skema: `WG client → wstunnel client → WS/WSS (80/8080/443/8443) → Nginx /wg-ws → wstunnel server 127.0.0.1:10081 → WG lokal 127.0.0.1:51820`.

- Binary statis `erebe/wstunnel v11.0.0` (~5 MB, tanpa deps), arsitektur `amd64/arm64/armv7/armv6/386`.
- Server: `wstunnel server --restrict-to 127.0.0.1:<WG_PORT> -r wg-ws -r wireguard-ws ws://127.0.0.1:10081` (prefix TANPA leading slash — cocok dengan Nginx).
- WireGuard murni UDP 51820 **tidak tersentuh** (fondasi tercepat tetap ada).

### 3. **AmneziaWG — WireGuard Anti-DPI (interface kedua `awg0:51821/udp`, menu 28/29)**

- Interface kedua `awg0` port `51821/udp` di samping `wg0` `51820/udp` (murni, untouched).
- Obfuskasi per-server `Jc/Jmin/Jmax/S1/S2/H1-H4` otomatis → disalin ke tiap `.conf` klien (kompatibel aplikasi resmi AmneziaVPN).
- Binary: paket distro dulu (`ppa:amnezia/ppa`, apt), lalu `amneziawg-go` (coba GitHub hanya bila `AWG_GO_TRY_GITHUB=1` — upstream hanya punya tags, belum ada binary rilis per 2026), **soft-skip** bila tidak ada (WG murni tetap jalan).
- `awg_find_bin()` **sengaja TIDAK** fallback ke `wg-quick` polos (itu stack WG murni — fallback diam-diam akan mengklaim "AmneziaWG aktif" padahal interface kedua polos).
- Unit systemd memakai path `awg-quick`/`wg-quick` hasil `command -v` (bukan hardcode `/usr/bin/`).
- Klien: `add-amneziawg-user.sh` / `remove-amneziawg-user.sh` baru (+ QR PNG), IP `10.66.77.0/24` + `fd42:42:77::/64` auto-increment.

### 4. **SSH-WS Pindah ke Backend Localhost (`127.0.0.1:10080`)**

- Bridge `ssh-ws.py` bind localhost-only; publik via gateway (`ws://IP:80/ssh-ws`, `ws://IP:8080/ssh-ws`, `wss://IP:8443/ssh-ws`, `wss://IP:443/ssh-ws`).
- Argumen lama `8080` otomatis diremap ke `10080` (backward compat).
- Uninstall menutup **kedua** port (`10080` + `8080` sisa v4.x).

### 5. **Engine v2ray-core yang Benar-Benar Kompatibel (menu 10)**

v2ray-core v5.53.0 **tidak punya** REALITY, XTLS-Vision, maupun transport XHTTP —
config v2ray kini **7 inbound saja** (3× WS `10001-10003` + 3× gRPC `10005-10007` + 1× TCP polos `10004`):

- Tanpa inbound REALITY/XHTTP/XTLS-Vision (sebelumnya config v2ray ikut-ikutan field Xray → `v2ray test` FAIL).
- Validasi engine-aware via `xray_test_config()` (`xray run -test -config` vs `v2ray test -c`); dipakai setup server + tambah/hapus user + menu 14 + status.
- Link generator engine-aware: judul 7 vs 13 protokol, rekomendasi v2ray (WS/gRPC/TCP polos), QR memakai link WS (bukan REALITY-XHTTP), blok summary tersimpan dibedakan.
- Firewall & uninstall menutup hanya port yang benar-benar di-bind per engine.

### 6. **SSL Hook Aman untuk Cron**

- `--reloadcmd` acme.sh hanya berisi perintah nyata (`systemctl reload-or-restart xray/nginx`) — fungsi shell `edge_refresh_tls` **tidak** ditaruh di sana (cron tidak punya fungsi shell kita → reload gagal diam-diam sebelumnya).
- `ssl_renew()` + `setup-ssl.sh` tetap memanggil `edge_refresh_tls()` langsung setelah issuance (gateway 8443 langsung pakai cert baru).

## 🔧 Perubahan Teknis

### File Baru

1. **`lib/edge.sh`** — Nginx gateway (install/write/refresh/remove, self-signed fallback, lazy Alpine path)
2. **`lib/wstunnel.sh`** — wstunnel server (download GitHub, unit systemd, instruksi klien)
3. **`lib/amneziawg.sh`** — server + klien AmneziaWG (obfuskasi, unit awg-quick generik)
4. **`add-amneziawg-user.sh` / `remove-amneziawg-user.sh`** — manajemen klien AWG (+ QR)
5. **`changelogs/v5.md`** — dokumen ini

### File yang Dimodifikasi

1. **`lib/xray.sh`** — XHTTP localhost + REALITY fallback 8443, config v2ray 7-inbound, `xray_test_config()`, link generator engine-aware, firewall per-engine, restart validator per-engine
2. **`lib/ssh.sh`** — WS bridge localhost `10080`, remap `8080→10080`
3. **`lib/ssl.sh`** — reloadcmd cron-safe (tanpa fungsi shell), refresh gateway best-effort
4. **`lib/edge.sh` + `setup-ssl.sh`** — `edge_refresh_tls()` setelah issuance
5. **`install.sh`** — langkah 15a (wstunnel) → 15a2 (gateway) → 15a3 (AWG), label inbound per-engine
6. **`menu.sh`** — menu 26/27/28/29, restart xray engine-aware, restart nginx aman (`nginx -t` lolos dulu)
7. **`status.sh`** — seksi gateway/wstunnel/AWG, config-test engine-aware, port REALITY disembunyikan di v2ray
8. **`uninstall.sh`** — cleanup gateway/wstunnel/AWG + firewall per-engine + tutup 8080 sisa
9. **`show-account.sh`** — blok AmneziaWG + info gateway SSH

### Kompatibilitas

- Upgrade dari v4.x aman: WS_PORT lama `8080` diremap, aturan firewall `8080` lama dibersihkan, param lama tanpa `XPORT_GW_*` default ke `80/8080/8443`.
- Pure WireGuard (`wg0` 51820/udp) + VLESS TCP REALITY (443) tetap fondasi tercepat — gateway hanya menambah jalur, tidak mengganti.
- Tanpa dependensi baru (nginx, python3, openssl, qrencode sudah ada di jalur masing-masing).

## 📦 Cara Verifikasi di VPS

```bash
# 1. Gateway menjawab di semua port
curl -s http://127.0.0.1:80/vmess -o /dev/null -w "%{http_code}\n"      # 400/101 via WS upgrade, bukan 404 polos bila backend hidup
curl -sk https://127.0.0.1:8443/vless -o /dev/null -w "%{http_code}\n"
sudo nginx -t && sudo systemctl is-active nginx wstunnel xray

# 2. Xray config valid + inbound count benar
sudo /usr/local/bin/xray run -test -config /etc/xray/config.json       # xray engine
# atau: sudo /usr/local/bin/xray test -c /etc/xray/config.json          # v2ray engine
python3 -c "import json;print(len(json.load(open('/etc/xray/config.json'))['inbounds']))"  # 13 (xray) / 7 (v2ray)

# 3. REALITY fallback ke gateway
sudo ss -lntp | grep -E ':443 |:8443 |:10080 |:10081 '

# 4. AmneziaWG (bila binary tersedia)
sudo systemctl is-active 'awg-quick@awg0' || sudo systemctl is-active awg0
sudo ./add-amneziawg-user.sh phone-awg && sudo ./show-account.sh phone-awg --qr

# 5. Uninstall bersih
sudo ./uninstall.sh --yes && sudo ss -lntp | grep -E ':8443 |:10081 ' || echo "gateway bersih"
```
